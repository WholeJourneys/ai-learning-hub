Understand & manage what you've built

You've made a lot of things across a lot of tools. The trick to not feeling lost is realizing every project lives in three separate layers. Get these straight and "where does this belong?" answers itself.

🌐
1. The address — Domains (GoDaddy)
A domain like traveldragon.com is just a signpost. GoDaddy's DNS points it at wherever your live site actually runs. Key rule: one domain points to one live place at a time — but you can add subdomains (like legacy.traveldragon.com) that point somewhere else.

3. The backup — Code & version history (GitHub)
GitHub is a filing cabinet for your code, not a live host for your apps. It keeps a safe copy and a history you can roll back to. (GitHub Pages can only serve simple static sites — not your database-backed apps.)

💡 The one-liner: GoDaddy = the address · Replit/Lovable = the engine that runs it · GitHub = the safety backup. Three different jobs — don't expect one to do another's.

The Travel Dragon domain swap — the plan

Big picture, in order. (Each step has click-by-click detail when you're ready — just ask.)

  1. Back up the old site first. Download a full copy so nothing is ever truly lost.
  2. Deploy Travel Dragon Reimagined on Replit (Autoscale, Reserved VM, or Static deployment).
  3. Preserve the old site: park it at legacy.traveldragon.com and keep its current host active for now.
  4. In GoDaddy DNS, point traveldragon.com to Replit — add the A records + the replit-verify TXT record Replit gives you.
  5. Wait for it to take (up to ~48h). Replit auto-adds the https padlock (SSL). Confirm the new site loads.
  6. Only then retire the old host if you want — wholejourneys.com stays completely untouched the whole time.
  • 🔒 Keep the replit-verify TXT record forever — if you delete it later, the site's security cert breaks and the site goes down.
  • 🧭 One domain = one live target. Want the old one too? Give it a subdomain (legacy.traveldragon.com).
  • 🪢 Never delete the old until the new is verified live. DNS changes are reversible, but a good backup means zero risk.

GitHub, in plain English

Think of GitHub as Dropbox for code, with a time machine. It's not where visitors go — it's your backup and history. Replit can connect to GitHub with a couple of clicks (a two-way sync), so every project gets a safe, versioned copy you could restore or hand to a developer later. Worth setting up for Travel Dragon and any experiment you care about; skip it for throwaway drafts.
